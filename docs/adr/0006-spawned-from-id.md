# 重複防止は子側spawnedFromId＋存在確認のみとする

生成された次回分が子側に生成元id（`spawnedFromId`）を持ち、チェック時は同一利用者に同idの子が既存なら生成しない（冪等）。解除時の連動削除はしない。不要なら利用者が手で削除する。

## Considered Options

- 親側に`nextTodoId`を持たせる: 子が削除されると存在しないIDが親に残り、実在確認の吸収処理が必須になるため不採用。子側なら削除と同時に関係が消える。
- 解除時に未完了の子を連動削除: 誤タップ取り消しには綺麗だが、自動生成分の消失が驚きになるため不採用。消失の驚き＞並びの気持ち悪さ。

## Consequences

`Todo.spawnedFromId: string | null`（手作成は`null`、生成時に親idを刻印）。MCP入力では受け付けず、`list/get`応答には読み取り専用で含める。`update`は lineage を不変に保つ。一意性は現状コード内スキャンで保証し、DB永続化導入時に unique 制約を貼る（宿題）。ADR-0005 の単発前進・月末丸め・追いつき無しは維持。
